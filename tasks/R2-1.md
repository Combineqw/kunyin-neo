【实现指令 → dsh】

## 目标
搭好 Rust 工具链,建立 aurora-native 原生模块骨架,
建成可复用的"影子对答案"框架,并让第一个模块
(库扫描/元数据解析)跑通对答案。
本块纯新增,禁止触碰任何现有业务代码。

## 执行步骤
1. 工具链:安装 rustup + stable 工具链 + MSVC 构建工具,
   cargo --version / rustc --version 输出正常才算就位
2. 建立 crates/aurora-native(napi-rs 脚手架,产物 .node):
   · 按模块分文件:src/scan.rs(本块完成)、
     src/lyrics.rs、src/settings_io.rs(仅建占位)
   · 统一错误枚举 + Result,关键路径禁裸 unwrap
   · 统一输出契约:所有函数返回 JSON,字段名与 Node 端
     完全一致——动手前先读现有扫描代码,登记字段映射表
     写入 PROJECT_STATUS AI 读层,再开始写代码
3. 扫描模块 src/scan.rs:
   · walkdir 递归扫描 + lofty 解析元数据
   · 输出数组,每项:title / artist / album /
     duration(秒) / path
   · 全链路只读,禁止任何写操作
4. 影子对答案框架 scripts/shadow-compare.mjs(本块核心资产):
   · 输入目录 → Node 引擎扫一遍 → Rust 引擎扫一遍
     → 逐首逐字段 diff → 输出中文人话报告:
     「共 N 首 · 一致 N · 不一致 0 → PASS」
     不一致时列前 20 条明细(哪首/哪字段/两边各是什么)
   · 必须通用:后续模块(歌词/设置)按约定注册即可,
     禁止把框架写死成只服务扫描
5. 一键入口:
   · npm run native:test = 编译 + 对答案 + 出报告
   · scripts/native-test.bat 双击可运行,输出全中文

## 测试素材
test-assets/ 放入 ≥50 首用户真实音乐(mp3/flac/ogg 混合),
从用户音乐文件夹复制,禁止生成假文件。

## 禁止事项
· 只允许新增文件,现有业务文件零改动
· 禁止接入主进程/UI(那是 R2-4 的事)
· 禁止任何写操作(影子阶段只读)
· 依赖白名单:napi 派生宏 / lofty / walkdir /
  serde / serde_json,超出即停
· 关键路径禁裸 unwrap,错误一律 Result
